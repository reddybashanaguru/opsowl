Notes & Collaboration

Investigators write structured case notes, comment on timeline events, mention colleagues, and build shared understanding — all in real time. Notes are the human narrative layer on top of AI analysis and ingested documents.

📄 Document: 06_NOTES_COLLABORATION
🏷️ Module: notes · collaboration
🔧 Editor: Tiptap v3
⚡ RT Push: SSE
📅 Version: 1.0.0
01

Feature Overview

Every investigation generates raw evidence — transactions, documents, timeline events, AI summaries — but investigations are ultimately resolved by human judgment. Notes & Collaboration is the layer where that judgment is captured, refined, and shared.

An investigator can annotate any case with a rich-text note, pin key findings, thread comments directly onto specific timeline events, and loop in colleagues with an @mention that triggers an instant notification. When a teammate posts a new note while you are viewing the case, your feed updates in real time via SSE — no page refresh, no missed context.

📝 Structured Notes

Rich text with headings, tables, code blocks, and bullet lists. Stored as HTML; plain text indexed for search.

💬 Threaded Comments

Comments attach to timeline events or notes. Nested replies (one level deep for MVP) keep discussions focused.

@ Mentions

Type @ inside any editor to surface active case members. Saved mentions trigger River notification jobs.

⚡ Real-time Feed

Combined activity feed per case, pushed via SSE. TanStack Query invalidation keeps UI fresh without polling.

🤖 AI-Assisted Notes

AI Copilot pre-fills note content. Human review required before save; badge tracks provenance.

📤 Formal Export

Formal notes compile into a single PDF report per case. Internal notes never leave the platform.

02

Note Types

Four distinct note types govern visibility, export eligibility, and authorship trust.

📋

Case Note

internal / formal

Rich-text note attached to the case root. Can be designated internal (team only) or formal (exportable). Supports pinning to the top of the note list. Primary artifact for investigator findings.

🗂️

Timeline Comment

event-attached

Comment linked to a specific timeline_event_id. Renders inline in the timeline workspace beneath its parent event. Useful for annotating a single suspicious transaction or document finding.

📄

Formal Note

exportable

A case note with note_type = 'formal'. Written with external audience in mind — regulators, compliance officers, auditors. Included in the case PDF report. Requires deliberate classification by author.

✨

AI-Generated Note

AI badge

Created by AI Copilot and pre-filled. Shows a prominent "AI Generated" badge (purple). Must be reviewed and edited by a human before saving. Once saved after edits, badge downgrades to "AI Assisted".

⚠️

MVP Scope: note_type enum covers 'internal' and 'formal'. AI provenance is tracked via a separate boolean column (ai_generated, ai_assisted) added in migration, not as a third enum value — keeping the export filter simple.

Database Schema

All tables follow the platform conventions: UUID v4 primary keys, TIMESTAMPTZ timestamps, soft-delete via deleted_at, foreign key enforcement enabled.

notes

CREATE TABLE notes (

Output Format

Tiptap produces two representations on save:

HTML — content column

Full rich text as HTML string. Used to render the note in the UI via dangerouslySetInnerHTML (sanitized with DOMPurify before render).

Plain Text — content_text column

Stripped plain text extracted from Tiptap JSON before save. Used by the full-text search indexer. Avoids indexing raw HTML tags.

JSON — transient

Tiptap internal JSON document used server-side in mention_parser.go to extract mention nodes. Never persisted; derived from submitted HTML on the API handler.

Server-Side Mention Parsing — mention_parser.go

// internal/notes/mention_parser.go
// Parses Tiptap JSON (re-derived from submitted HTML) to extract mentioned user IDs

package notes

type TiptapNode struct {
    Type    string       `json:"type"`
    Attrs   map[string]any `json:"attrs,omitempty"`
    Content []TiptapNode  `json:"content,omitempty"`
}

// ExtractMentions walks the Tiptap JSON tree and collects all mention node user IDs.
func ExtractMentions(root TiptapNode) []string {
    var ids []string
    var walk func(n TiptapNode)
    walk = func(n TiptapNode) {
        if n.Type == "mention" {
            if id, ok := n.Attrs["id"].(string); ok {
                ids = append(ids, id)
            }
        }
        for _, child := range n.Content {
            walk(child)
        }
    }
    walk(root)
    return ids
}

Activity Feed

The activity feed provides a unified, chronological view of all collaboration events on a case — notes created or edited, comments added, and mentions. It is the collaboration command center, showing the team's investigative narrative as it unfolds.

Feed Composition

Notes

Each note creation and edit appears as a feed entry with title, author, type badge, and a 200-character excerpt.

Comments

Comments on events or notes appear with context — "commented on Transaction T-4829" or "replied to Priya's note".

Pinned items

Pin/unpin actions appear as feed events for visibility — e.g., "Rohan pinned a note".

Feed Query — Activity Feed SQL

-- Combined activity feed: notes + comments, newest first, cursor paginated
SELECT
  'note'     AS event_type,
  n.id       AS source_id,
  n.title    AS summary,
  LEFT(n.content_text, 200) AS excerpt,
  n.author_id,
  n.created_at
FROM   notes n
WHERE  n.case_id = $1 AND n.deleted_at IS NULL

UNION ALL

SELECT
  'comment'  AS event_type,
  c.id        AS source_id,
  COALESCE(te.description, 'a note') AS summary,
  LEFT(c.content, 200) AS excerpt,
  c.author_id,
  c.created_at
FROM   comments c
LEFT JOIN timeline_events te ON te.id = c.timeline_event_id
WHERE  c.case_id = $1 AND c.deleted_at IS NULL

ORDER BY created_at DESC
LIMIT  $2    -- page size (default 25)
OFFSET $3;   -- cursor-based: WHERE created_at < :cursor
💡

Performance: The activity feed is virtualized in the frontend using @tanstack/react-virtual to handle cases with thousands of events. The backend always uses cursor pagination (keyed on created_at + id) — never offset.

Real-time Collaboration via SSE

Server-Sent Events deliver real-time collaboration updates to all users currently viewing a case. The Go service maintains a per-case SSE broker that fans out events to connected clients. No WebSocket negotiation is required — SSE is simpler, HTTP/1.1 compatible, and sufficient for the one-directional push pattern needed here.

Go SSE Broker Sketch

// internal/collaboration/sse_broker.go

type CaseBroker struct {
    mu      sync.RWMutex
    clients map[string]map[string]chan Event  // caseID → clientID → channel
}

func (b *CaseBroker) Subscribe(caseID, clientID string) chan Event {
    ch := make(chan Event, 32)
    b.mu.Lock()
    defer b.mu.Unlock()
    if b.clients[caseID] == nil {
        b.clients[caseID] = make(map[string]chan Event)
    }
    b.clients[caseID][clientID] = ch
    return ch
}

func (b *CaseBroker) Publish(caseID string, evt Event) {
    b.mu.RLock()
    defer b.mu.RUnlock()
    for _, ch := range b.clients[caseID] {
        select {
        case ch <- evt:
        default:  // drop if client is slow; client will refetch on reconnect
        }
    }
}
⚠️

MVP constraint — no simultaneous editing: Two investigators cannot edit the same note at the same time. There is no optimistic locking or operational transform. If a concurrent edit occurs, last-write wins (the second PUT overwrites). A user-facing warning for concurrent edits is a Phase 2 enhancement.

💭

Phase 2 — Typing Indicator: SSE can carry a user_typing event (debounced, sent on Tiptap onUpdate) to show a "Priya is editing this note..." indicator to other viewers. This requires a lightweight heartbeat mechanism and is deferred post-MVP.

AI Integration

The AI Copilot can draft notes pre-filled with synthesized case context — summaries, risk narratives, key transaction highlights. Human review is mandatory before the note is persisted as final.

AI Generated

Note was created by AI Copilot and has not yet been reviewed or edited by a human. Rendered with a prominent purple badge. Cannot be included in PDF report until edited.

AI drafted the note but a human has since edited and saved it. Indigo badge — lower visual prominence. Eligible for formal export. Provenance is preserved for audit.

12

Export

Formal notes are the authoritative output artifacts of an investigation. They can be compiled into a single PDF report per case, suitable for sharing with compliance officers, regulators, or legal counsel.

Eligibility

Only notes with note_type = 'formal' and ai_generated = false are included. Draft AI-generated notes are excluded until a human edits and saves them.

Ordering

Notes appear in the PDF in chronological order (created_at ASC). Pinned notes are not given priority in export — export order is temporal.

Content

Note HTML is rendered to PDF. Tiptap-generated HTML is clean and structured — headings, tables, bullet lists render faithfully via Go's PDF library (chromedp headless or wkhtmltopdf for MVP).

GET /api/v1/cases/:id/report/export Auth: reviewer / supervisor
Compile all formal notes on the case into a single PDF report and return it as a file download. The response content type is application/pdf with Content-Disposition: attachment. PDF generation is synchronous for MVP (acceptable for cases with <50 formal notes). Async generation via River job is a Phase 2 enhancement for large cases.
Query ParamTypeDescription
include_metadataboolean optionalInclude case header (ID, title, dates, assignee) on cover page. Default true.
✅

MVP Scope: PDF report is a basic compilation of formal notes. Branding (logo, header/footer), table of contents, and digital signature are Phase 2 features. The endpoint is built now with a simple layout so Phase 2 can layer styling on top.

Test Strategy

Tests are written at the unit, integration, and end-to-end levels. Go tests use testing + testify; frontend tests use Vitest + Testing Library.

🔬
Tiptap content parsing: Unit tests for the frontend HTML-to-plaintext extractor — verify tables, nested lists, code blocks, and blockquotes are correctly stripped. Edge cases: empty content, malformed HTML, XSS payloads (DOMPurify integration).
🔬
Mention extraction tests (mention_parser.go): Unit tests for ExtractMentions — deeply nested mention nodes, duplicate mentions (same user twice → deduplicated), note with zero mentions, non-mention nodes not captured.
🗄️
Activity feed ordering tests: Integration tests against a test Postgres instance — verify UNION query returns correct chronological order across notes and comments, cursor pagination produces non-overlapping pages, deleted items excluded, pinned notes do not affect feed order.
⚙️
River notification job tests: Unit tests for MentionNotificationJob — mock notification service, verify correct payload construction, idempotency on duplicate job insertion, dead-letter handling on notification failure.
⚡
SSE push tests: Integration tests for CaseBroker — subscribe a test client, publish an event, assert delivery within timeout. Verify slow client drop (non-blocking send) does not block other subscribers. Verify Unsubscribe cleans up channel.
