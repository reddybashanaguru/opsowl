1 · About Aye Finance & Scenario Context

Who is Aye Finance?
Aye Finance Limited is a Delhi-based NBFC that provides micro and small business loans (₹30,000 – ₹15 lakh) to semi-urban and rural entrepreneurs across Tier 2/3 cities — kirana owners, textile traders, hardware dealers, artisans. As an RBI-registered NBFC, it is a "Reporting Entity" under PMLA 2002 and must maintain a full AML/CFT programme including KYC, transaction monitoring, CTR/STR filing with FIU-IND, and annual audit by the CCO.

7 · Issues & Bugs Found

✅ RESOLVED — AI Service Running (Docker) — False Alarm
Where: GET /api/v1/cases/{id}/insights returns ai_available: false before first analysis is triggered
Root cause confirmed: The AI service (opsowl-ai) and Ollama (opsowl-ollama) are running as Docker containers. Both showed unhealthy status due to incorrect healthcheck commands (curl/wget not present in those images) — not due to actual service failure.
Fix applied: Healthchecks updated to use bash TCP check (Ollama) and python3 urllib (AI service). Containers recreated — both now show healthy. AI analysis confirmed working: POST /insights/analyse returns risk_score, risk_level, recommended_actions with model: rule-based + Ollama qwen2.5:7b.
Action item: Set matching AI_SERVICE_SECRET in apps/api/.env to enable richer LLM-backed analysis.
✅ RESOLVED — SLA Policies & Case Templates — Simulation Path Error, Not a Bug
Where: Simulation curl calls used wrong paths: /api/v1/sla-policies and /api/v1/case-templates
Correct paths: /api/v1/sla/policies  |  /api/v1/templates
Verification: Routes are correctly registered in the router. The frontend settings pages already call the correct paths and work fine. No backend change was needed.
Dashboard SLA breach count (40/49): Caused by old E2E test cases with past-due SLA deadlines from previous test runs. Configuring realistic SLA policies (sanctions=24h, AML=72h, PEP=240h) and archiving test cases will normalise this stat.
✅ FIXED — Auto-Converted Cases Get Generic Titles
Where: apps/api/internal/alerts/service.go — auto-conversion title generation
Before: [CASH_STRUCTURING] Subject Name
After: Cash Structuring – Subject Name (AccountNumber) — title-cased, human-readable, account appended when present
Fix applied: Changed from fmt.Sprintf("[%s] %s", alert.AlertType, alert.SubjectName) to a proper title-case conversion splitting on underscores with em-dash separator and optional account suffix.
✅ FIXED — Auto-Assigned Cases Go to Default Admin User
Where: Alert Rules creation modal in Settings → Alert Routing Rules
Root cause: The backend AlertRule DTO already had AutoAssignUserID *uuid.UUID field, but the frontend CreateRuleModal never sent it — the field was entirely missing from the form.
Fix applied: Added "Auto-assign Analyst" picker to CreateRuleModal. The dropdown appears only when Mode = Auto, lists all analysts/managers from /api/v1/users, and sends auto_assign_user_id in the mutation payload. Rule cards now show "Assigns to: [name]" for auto rules. Existing rules that had no assignment still fall back to admin queue.
🟠 HIGH — Dashboard SLA Breach Count Seems Inflated (40/49)
Where: GET /api/v1/dashboard/stats → sla_breached: 40 out of 49 open cases
Impact: If 81% of all open cases are shown as SLA-breached, the "Attention Required" panel becomes meaningless — analysts cannot triage by urgency. This is data quality issue or misconfigured SLA policies.
Root cause: Old E2E test cases from previous test runs may have SLA deadlines set to the past, or SLA policies were never configured (defaulting to 0-hour SLA = always breached).
Fix: Set realistic SLA policies (e.g., sanctions = 24h, AML = 72h, PEP = 240h). Archive or close old E2E test cases.
🟡 MEDIUM — Task Comments URL Bug (Fixed This Session)
Where: Task detail page at /cases/[id]/tasks/[taskId] → "COMMENTS (1)" count but list shows "No comments yet"
Root cause: useInfiniteQuery queryFn built URL as /comments&limit=20 (& without preceding ?) — malformed URL returned empty results from API.
Status: ✅ Fixed in this session — changed to ?limit=20 or ?cursor=X&limit=20.
🟡 MEDIUM — Notes Empty State Shows While Editor is Open (Fixed This Session)
Where: Notes page at /cases/[id]/notes → "No notes yet / Write the first note →" shows below the active note editor when composing
Root cause: Empty state condition was allNotes.length === 0 without checking !showEditor.
Status: ✅ Fixed in this session — changed to allNotes.length === 0 && !showEditor.
🟡 MEDIUM — Communications Endpoint Naming Inconsistency
Where: API route is POST /api/v1/cases/{id}/comms but initial attempts used /communications → 404
Impact: API consumers (integrations, Postman collections) may use /communications and get silent 404 failures.
Fix: Either add /communications as an alias, or standardise all documentation and frontend to use /comms.
✅ RESOLVED (Platform Patch v1.0.1) — 6 Platform-Wide Fixes Applied
The following fixes were shipped in OpsOwl v1.0.1 following cross-client evaluation feedback. All are relevant to Aye Finance production deployments:

(1) AI Copilot Embedding Graceful Failure: /ask, /generate-note, /extract-actions now return INSUFFICIENT_CONTEXT gracefully instead of 500 INTERNAL_ERROR when the LLM embedding model is momentarily unavailable. The AI service no longer crashes on transient model warm-up delays.

(2) Cases Default to Open: Manually created cases via POST /cases now start with status=open. Previously, manual cases started as draft and required a separate PATCH to appear in the analyst queue. The draft→open transition is still valid for legacy cases.

(3) SLA Auto-Set from Priority: sla_breach_at is computed automatically at case creation using priority-to-SLA mapping. Aye Finance cases will now have correct SLA breach timers from creation — the 40/49 breach count issue partly stems from cases with no SLA set; new cases will all have deadlines.

(4) Search ILIKE Fallback: When tsvector full-text search returns 0 results, the service automatically falls back to ILIKE pattern matching against case titles, descriptions, and case numbers. Search is now reliable immediately after data insertion.

(5) Descriptive API Type Errors: JSON decode errors now return field-specific messages: field "amount" must be float64 (got string). Reduces integration debugging time for API consumers and integration scripts.

(6) AI Narrative Auth Secured: The /narrative/generate AI endpoint now validates service-to-service Authorization header. The Go narrative service sends the correct bearer token. Closes a security gap in deployments with AI_SERVICE_SECRET configured.
ℹ️ INFO — No FIN-NET Export Format
Where: STR filing workflow creates the narrative and subject details in OpsOwl but there is no export to FIN-NET XML format required for actual FIU-IND submission.
Impact: Analysts must manually copy STR narrative into the FIU-IND FIN-NET portal. This is a critical gap for production use — it defeats the purpose of digital STR management.
Fix (Phase 2): Add "Export to FIN-NET XML" button on the filed STR. Map OpsOwl STR fields to FIN-NET schema. This is a high-value feature for Indian NBFC clients.
ℹ️ INFO — No Deduplication of Related Alerts Across Cases
Where: Alerts AYF-AML-2024-001 (Structuring) and AYF-AML-2024-006 (CTR) are both about Rajendra Prasad Gupta and were converted to separate cases (OWL-00955 and OWL-00958). There is no mechanism to link these as related investigations.
Impact: Two analysts may independently work the same subject. CTR case and AML structuring case have no formal relationship in the system.
Fix (Phase 2): Add "Linked Cases" field on case detail. Implement a "Related Alerts" panel showing other alerts for the same subject.
