Feature 04 MVP · AI Service (Python)

AI Copilot & Investigation Agent

Two complementary AI modes: a RAG Copilot that answers questions on uploaded documents, and an Autonomous Investigation Agent that reads the full case — notes, tasks, findings, transactions, timeline — and produces a structured investigation report without analyst hand-holding.

Feature Overview

OpsOwl AI has two distinct intelligence modes that work together in the same panel. The Copilot is document-focused and interactive — you ask, it answers from PDFs. The Agent is autonomous and case-wide — you set a goal, it investigates everything and reports back. Neither replaces the analyst; both compress hours of work into minutes.

Core Principle
All AI outputs — both Copilot responses and Agent reports — are visible to the analyst in the UI. The Agent is read-only: it can observe any case data but cannot write, mutate, or submit anything. Human action is always required to act on AI findings.

AI Capabilities

RAG Copilot (document-focused, interactive)

📄 Case Summarization
Multi-document summarization across all case documents. Produces a structured summary with key facts, entities, and timeline. Async operation — results streamed back via SSE.
❓ Document Q&A (RAG)
Ask natural language questions about uploaded documents. Uses pgvector similarity search to retrieve relevant chunks, augments the prompt, and returns an answer with exact citations (doc name, page, excerpt).
📝 Note Generation
AI drafts investigation notes from document context. Analyst reviews, edits, and saves. Saved notes show "AI Assisted" badge. Draft is never auto-saved — human action required.
✅ Action Item Extraction
Analyzes documents to extract actionable items. Returns a list of suggested tasks. Analyst accepts, modifies, or rejects each suggestion before tasks are created.

⚡ Autonomous Investigation Agent (case-wide, multi-step)

Give the agent a goal in plain English. It autonomously reads the full case — notes, tasks, findings, transactions, timeline, documents — calls tools in sequence, reasons across all gathered data, and produces a structured investigation report. Analyst watches every step live via SSE streaming.

🔁 Multi-Step Reasoning Loop
Agent calls tools one by one, inspects results, decides what to investigate next. Continues until it has enough data or reaches the 10-iteration safety limit. Never calls the same tool twice with the same input.
📡 Live SSE Event Stream
Every reasoning step, tool call, tool result, and final answer streams to the analyst in real time. No waiting — analyst sees the agent's thinking as it happens. Frontend uses fetch() + ReadableStream (not EventSource — POST body needed).
🔒 Read-Only Tools
All 8 tools are strictly read-only. The agent can observe any case data but cannot create notes, close cases, file STRs, or mutate anything. Write operations always require explicit human UI action.
🏠 On-Premise Compatible
Anthropic path: AsyncAnthropic with native tool_use. Ollama path: /api/chat with OpenAI-compatible tools format (qwen2.5:7b, mistral-nemo). Set DEFAULT_PROVIDER=ollama — zero data leaves the network.

SSE Proxy (Go → Python)

The Go API's StreamAgent() method POSTs to POST /agent/{case_id}/run on the Python service and pipes the response body byte-by-byte to the HTTP client using io.Copy + http.Flusher. The agent route uses a separate chi router group with no timeout middleware — agent runs live as long as the connection is open.

Database Schema

-- AI interaction log (immutable — no UPDATE/DELETE)
CREATE TABLE ai_logs (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  case_id               UUID NOT NULL REFERENCES cases(id),
  triggered_by          UUID NOT NULL REFERENCES users(id),
  action_type           VARCHAR NOT NULL CHECK (action_type IN (
                          'summarize','ask','generate_note','extract_actions','pattern_detect'
                        )),
  prompt_text           TEXT NOT NULL,                    -- after PII masking
  response_text         TEXT NOT NULL,
  model_used            VARCHAR NOT NULL,                 -- e.g. 'claude-opus-4'
  provider              VARCHAR NOT NULL,                 -- 'anthropic' | 'openai'
  tokens_input          INT NOT NULL,
  tokens_output         INT NOT NULL,
  latency_ms            INT NOT NULL,
  confidence_score      NUMERIC(3,2) CHECK (confidence_score BETWEEN 0 AND 1),
  citations             JSONB NOT NULL DEFAULT '[]',
  human_review_status   VARCHAR NOT NULL DEFAULT 'pending'
                          CHECK (human_review_status IN ('pending','approved','rejected','edited')),
  reviewed_by           UUID REFERENCES users(id),
  reviewed_at           TIMESTAMPTZ,
  human_edited_response TEXT,
  created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_ai_logs_case ON ai_logs(case_id, created_at DESC);
CREATE INDEX idx_ai_logs_review ON ai_logs(human_review_status, created_at);
CREATE INDEX idx_ai_logs_user ON ai_logs(triggered_by, created_at DESC);

-- Versioned prompt registry
CREATE TABLE ai_prompts (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name            VARCHAR NOT NULL,
  slug            VARCHAR NOT NULL,
  version         INT NOT NULL,
  template        TEXT NOT NULL,           -- Jinja2 template
  task_type       VARCHAR NOT NULL,
  variables       JSONB NOT NULL,          -- expected template vars
  is_active       BOOL NOT NULL DEFAULT true,
  ab_test_weight  NUMERIC(3,2) DEFAULT 1.0,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE(slug, version)
);

-- Document chunks for RAG
CREATE TABLE document_chunks (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id   UUID NOT NULL REFERENCES documents(id),
  case_id       UUID NOT NULL REFERENCES cases(id),
  chunk_index   INT NOT NULL,
  content       TEXT NOT NULL,
  embedding     vector(1536),             -- OpenAI text-embedding-3-small
  page_number   INT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_chunks_case ON document_chunks(case_id);
CREATE INDEX idx_chunks_embedding ON document_chunks USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);

8 Anti-Hallucination Rules

RULE 1
Every response cites its source
Python RAG service retrieves top-k chunks and includes [{doc_id, doc_name, page, excerpt, similarity_score}] in the response JSON. Stored in citations JSONB. Frontend renders citation cards — cannot render AI response without them.
RULE 2
Confidence score on every output
Computed from cosine similarity of top-k chunks (RAG) or context richness score (summarization). Stored as confidence_score NUMERIC(3,2). Shown as colored bar: ≥0.8 green, 0.5–0.79 amber, <0.5 red with mandatory review warning.
RULE 3
"I don't have enough context" when context is insufficient
System prompt includes: "If you cannot answer from the provided context, respond with exactly: INSUFFICIENT_CONTEXT". Python response parser detects this sentinel → returns structured error to frontend → UI shows "Not enough documents in this case to answer that question."
RULE 4
Human review gate before any AI output becomes official
All responses default human_review_status='pending'. Case record only shows approved/edited entries. API enforces this — case summary endpoint filters out pending AI outputs for external display.
RULE 5
AI content always visually distinct
AICard React component always renders with: violet left border, "AI Generated" badge, confidence bar, citations panel, review status badge. Component cannot be rendered without these props — TypeScript enforces it.
RULE 6
Prompt injection prevention
Python service sanitizes all user input: strip HTML tags, escape special characters, detect adversarial patterns ("ignore previous instructions", "you are now", "disregard") — reject with 400 error if detected. Sanitized input logged for audit.
RULE 7
PII masking before every LLM call
Presidio Analyzer detects entities (PAN, Aadhaar, phone, email, account numbers). Replaced with tokens: [PAN_1], [PHONE_1]. LLM never sees raw PII. ai_logs.prompt_text stores masked version only.
RULE 8
Every prompt + response stored in ai_logs
Python AI service calls POST /internal/ai/log after every LLM call. If logging fails, the response is discarded and an error returned to the user. Logging is not optional.

Human Review Gate

The flow from AI generation to official case record:

AI generates response
→
Stored: status=pending
→
Shown with amber "PENDING REVIEW" banner
✓ Approve → status=approved
✏ Edit → human modifies → status=edited
✗ Reject → reason required → status=rejected, discarded

All review actions emit an event to audit_logs. Approved/edited responses show "VERIFIED" badge (green). Rejected responses visible in AI history with rejection reason.

Frontend Components

CopilotPanel (5 tabs)
Slide-out drawer from case detail. Tabs: Ask · Summarize · Draft Note · Extract Tasks · ⚡ Agent. Opens via Cmd+Shift+A. Each tab is independent — no shared state between RAG and Agent modes.
useAgentStream hook
fetch() + ReadableStream SSE consumer. Parses event/data lines, maintains events[] array, exposes answer, stats, run(goal), cancel(), reset(). AbortController cancels in-flight streams.
Agent Event Feed
Live streaming feed — each SSE event renders as a row: → Case Context (tool_call), ✓ preview text (tool_result ok), ✗ error (tool_result !ok), italic reasoning (thinking). Auto-scrolls to bottom.
Investigation Report Card
Rendered after answer event. Shows full markdown report, token/iteration stats from done event, and "Run again" reset button. Cyan border visually distinct from RAG response cards.
AICard (RAG Copilot)
Renders Copilot responses with violet left border, "AI Generated" badge, confidence bar, citations panel, and human review actions (Approve / Edit / Reject). TypeScript enforces all required props.
Review Gate (Copilot only)
All RAG Copilot outputs go through PENDING → APPROVED/REJECTED/EDITED workflow. Agent reports are read-only observations — they do not enter the AI log as reviewable items.
