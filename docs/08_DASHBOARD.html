Dashboard

The ops manager's command centre. At a glance: total cases, what's overdue, who's overloaded, AI activity, and SLA health — all refreshed every 30 seconds. Purpose-built for investigation team leads, not generic analytics.

Feature Overview

The dashboard answers the questions an ops manager asks every morning: "How many cases are open? Who has too many? Are we breaching SLAs? Does anything need my attention right now?" It is deliberately simple and action-oriented — clicking any widget navigates to the filtered case list.

Performance Architecture
All dashboard data is served from PostgreSQL materialized views refreshed every 5 minutes by a River background job. API responses include Cache-Control: max-age=30. Zero live aggregate queries on the critical path.

Materialized Views

-- Case summary counts
CREATE MATERIALIZED VIEW mv_case_summary AS
SELECT
  status,
  priority,
  COUNT(*) AS total,
  COUNT(*) FILTER (WHERE due_date < NOW() AND status NOT IN ('closed','cancelled')) AS overdue,
  COUNT(*) FILTER (WHERE created_at >= NOW() - INTERVAL '7 days') AS created_this_week,
  COUNT(*) FILTER (WHERE updated_at >= NOW() - INTERVAL '7 days' AND status = 'closed') AS closed_this_week
FROM cases
WHERE deleted_at IS NULL
GROUP BY status, priority;

CREATE UNIQUE INDEX ON mv_case_summary(status, priority);

-- Team workload
CREATE MATERIALIZED VIEW mv_team_workload AS
SELECT
  u.id AS user_id,
  u.full_name,
  COUNT(c.id) AS open_case_count
FROM users u
LEFT JOIN cases c ON c.assigned_to = u.id
  AND c.status NOT IN ('closed','cancelled')
  AND c.deleted_at IS NULL
WHERE u.is_active = true
GROUP BY u.id, u.full_name;

CREATE UNIQUE INDEX ON mv_team_workload(user_id);

-- SLA health
CREATE MATERIALIZED VIEW mv_sla_health AS
SELECT
  priority,
  COUNT(*) AS total,
  COUNT(*) FILTER (WHERE sla_breach_at > NOW()) AS within_sla,
  COUNT(*) FILTER (WHERE sla_breach_at <= NOW()) AS breached,
  ROUND(
    COUNT(*) FILTER (WHERE sla_breach_at > NOW()) * 100.0 / NULLIF(COUNT(*), 0), 1
  ) AS compliance_pct
FROM cases
WHERE status NOT IN ('closed','cancelled')
  AND deleted_at IS NULL
GROUP BY priority;

CREATE UNIQUE INDEX ON mv_sla_health(priority);

-- AI activity daily
CREATE MATERIALIZED VIEW mv_ai_activity_daily AS
SELECT
  DATE(created_at) AS activity_date,
  COUNT(*) AS total_queries,
  COUNT(*) FILTER (WHERE human_review_status = 'pending') AS pending_reviews,
  SUM(tokens_input + tokens_output) AS total_tokens
FROM ai_logs
WHERE created_at >= NOW() - INTERVAL '30 days'
GROUP BY DATE(created_at);

CREATE UNIQUE INDEX ON mv_ai_activity_daily(activity_date);

Refresh Job (River)

// River job — runs every 5 minutes
type RefreshMaterializedViewsArgs struct{}

func (w *MVRefreshWorker) Work(ctx context.Context, job *river.Job[RefreshMaterializedViewsArgs]) error {
    views := []string{
        "mv_case_summary",
        "mv_team_workload",
        "mv_sla_health",
    }
    for _, view := range views {
        _, err := w.db.Exec(ctx,
            fmt.Sprintf("REFRESH MATERIALIZED VIEW CONCURRENTLY %s", view))
        if err != nil {
            return fmt.Errorf("refresh %s: %w", view, err)
        }
    }
    return nil
}

AI queries today, documents processed, pending reviews. From mv_ai_activity_daily + live pending count.
GET/api/v1/dashboard/recent-activity
Last 20 timeline events across all accessible cases. Live query (not materialized — small result set). Filtered by role.

Current user: my open cases, my tasks due today, my pending AI reviews, my mentions unread. Any role.
GET/api/v1/dashboard/case-age
Age distribution of open cases in buckets: <1d, 1–3d, 3–7d, 7–30d, >30d. Cache-Control: max-age=60.
GET/api/v1/dashboard/stream
SSE endpoint. Pushes dashboard_update event when case counts change (status change, new case, closure). Client refetches summary widgets on receive.

Real-time Updates

Dashboard widgets don't need millisecond freshness — 30-second cache is acceptable for an operations dashboard. Real-time mechanism is lightweight:

  1. Client connects to SSE stream at /api/v1/dashboard/stream
  2. When a case status changes anywhere in the system → Go publishes dashboard_update SSE event
  3. Client receives event → TanStack Query invalidates dashboard queries → refetch triggered
  4. Widgets update with fresh data from materialized views (data may be up to 5 min old)

Frontend Components

MetricCard
Props: label, value, trend ('up'|'down'|'neutral'), delta, color, onClick (navigates to filtered case list). Skeleton loading state.
SLARingChart
SVG circle with stroke-dasharray for percentage. Props: compliance_pct, breached_count. CSS-only — no chart library dependency.
WorkloadBar
Horizontal bar per analyst. Color: green <5, amber 5–10, red >10. Click analyst → filter case list by assignee.
ActivityFeedItem
Icon per event type, actor avatar, case name link, relative time. Virtualized list (react-window) for performance on large feeds.
CaseAgeBucket
Horizontal bar chart, click any bucket → navigates to case list filtered by age range. CSS bars only.
DashboardLayout
CSS Grid: 4-col on desktop → 2-col on medium → 1-col on mobile. TanStack Query with SSE invalidation. Date range picker for filters (Today / This Week / This Month / Custom).

Performance Strategy

Materialized Views
Aggregations computed offline every 5 min. Dashboard queries are simple SELECTs on pre-computed tables — sub-millisecond response regardless of case volume.
30s Client Cache
Acceptable for ops dashboard. Avoids hammering DB on every page visit. SSE invalidation ensures important changes (new overdue case) propagate quickly.
Phase 2 Upgrade
Add Redis cache in front of materialized view queries when dashboard latency >200ms consistently. Trigger: measured production bottleneck — not preemptive.
