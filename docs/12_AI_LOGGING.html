AI Logging & Explainability

Every AI action in OpsOwl AI is logged, explainable, and auditable. Regulated clients (fintechs, NBFCs) must prove to regulators that AI decisions were reviewed by humans. This is not a nice-to-have — it is the feature that makes OpsOwl AI sellable to BFSI enterprises.

Critical — Non-Negotiable
Without AI logging and explainability, no fintech, NBFC, or lending company will deploy OpsOwl AI in a regulated environment. RBI AI governance guidelines explicitly require human oversight, audit trails, and explainability for AI used in financial operations.

Feature Overview

AI Logging captures the complete lifecycle of every AI interaction: what was asked, what context was used, what the model responded, how confident it was, which sources it cited, and what a human decided to do with the output. This data serves three purposes:

🏛️ Regulatory Compliance
Prove to RBI/SEBI auditors that every AI decision was reviewed by a human, with full trail of who approved what and when.
🔍 Explainability
Investigators can see exactly why the AI said what it said — which documents, which excerpts, with what confidence level.
📊 Continuous Improvement
Track approval rates, rejection reasons, and confidence accuracy to improve prompts and model selection over time.

Database Schema

CREATE TABLE ai_logs (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  case_id               UUID NOT NULL REFERENCES cases(id),
  triggered_by          UUID NOT NULL REFERENCES users(id),
  action_type           VARCHAR NOT NULL CHECK (action_type IN (
                          'summarize','ask','generate_note','extract_actions','pattern_detect'
                        )),
  -- Prompt stored AFTER PII masking — never log raw PII
  prompt_text           TEXT NOT NULL,
  response_text         TEXT NOT NULL,
  model_used            VARCHAR NOT NULL,
  provider              VARCHAR NOT NULL,
  tokens_input          INT NOT NULL,
  tokens_output         INT NOT NULL,
  latency_ms            INT NOT NULL,
  confidence_score      NUMERIC(3,2) CHECK (confidence_score BETWEEN 0 AND 1),
  -- citations: [{doc_id, doc_name, page, excerpt, similarity_score}]
  citations             JSONB NOT NULL DEFAULT '[]',
  human_review_status   VARCHAR NOT NULL DEFAULT 'pending'
                          CHECK (human_review_status IN (
                            'pending','approved','rejected','edited'
                          )),
  reviewed_by           UUID REFERENCES users(id),
  reviewed_at           TIMESTAMPTZ,
  human_edited_response TEXT,
  created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW()
  -- NO deleted_at — AI logs are immutable
);

CREATE INDEX idx_ai_logs_case        ON ai_logs(case_id, created_at DESC);
CREATE INDEX idx_ai_logs_review      ON ai_logs(human_review_status, created_at);
CREATE INDEX idx_ai_logs_user        ON ai_logs(triggered_by, created_at DESC);
CREATE INDEX idx_ai_logs_action      ON ai_logs(action_type, created_at DESC);

-- Versioned prompt registry
CREATE TABLE ai_prompts (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name            VARCHAR NOT NULL,
  slug            VARCHAR NOT NULL,
  version         INT NOT NULL,
  template        TEXT NOT NULL,        -- Jinja2 template
  task_type       VARCHAR NOT NULL,
  variables       JSONB NOT NULL,       -- list of expected variable names
  is_active       BOOL NOT NULL DEFAULT true,
  ab_test_weight  NUMERIC(3,2) DEFAULT 1.0,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (slug, version)
);

Confidence Score Calculation

Confidence is computed differently per action type and stored as a 0.0–1.0 value:

Action TypeCalculation Method
ask (RAG Q&A)Average cosine similarity of top-k pgvector chunks. High similarity = AI had strong context to draw from.
summarizeSource coverage ratio: (available context tokens / ideal context tokens) × chunk relevance score average.
generate_noteHeuristic: number of case documents + events + notes available. More context = higher confidence.
extract_actionsSame heuristic as generate_note, weighted by document processing completeness.
pattern_detectSimilarity score to matched past cases in pgvector store.

Confidence Thresholds

≥ 0.80
High Confidence
Green bar. Analyst may approve quickly. Still requires review.
0.50–0.79
Medium Confidence
Amber bar. "Review recommended" label. Read citations carefully before approving.
< 0.50
Low Confidence
Red bar. "Please verify carefully" warning. Edit before approving is strongly recommended.

Human Review Gate

The complete state machine for every AI output:

                         ┌─────────────────────┐
  AI generates response  │   status: pending    │  ← Default on creation
                         │   amber "PENDING"     │
                         │   badge in UI         │
                         └──────────┬──────────┘
                                    │
               ┌────────────────────┼──────────────────────┐
               ▼                    ▼                       ▼
    ┌──────────────────┐  ┌─────────────────────┐  ┌──────────────────┐
    │  status: approved│  │   status: edited    │  │ status: rejected │
    │  green "VERIFIED"│  │   blue "AI Assisted"│  │  red "REJECTED"  │
    │  badge in UI     │  │  human_edited_text  │  │  reason stored   │
    └──────────────────┘  └─────────────────────┘  └──────────────────┘
    All transitions emit to audit_logs with reviewer + timestamp

Once approved or edited, the AI output is included in the official case record. Rejected outputs are visible only in AI history (with rejection reason) and never appear in case summaries or reports.

API Endpoints

GET/api/v1/ai/logs
All AI logs. Manager/Admin only. Filter: case_id, action_type, human_review_status, triggered_by, date_from, date_to. Cursor paginated.
GET/api/v1/cases/:id/ai/logs
Case-scoped AI history. All roles with case access. Shows full interaction history with review status.
GET/api/v1/ai/logs/:id
Single log detail: full prompt text, full response, all citations, review history. Admin/Manager only (full prompt visible).
POST/api/v1/ai/logs/:id/approve
Approve AI output. Sets status=approved, records reviewed_by + reviewed_at. Emits audit event.
POST/api/v1/ai/logs/:id/reject
Reject AI output. Body: {reason: string}. Output excluded from case record. Emits audit event.
PUT/api/v1/ai/logs/:id/edit
Human edits AI output. Body: {edited_response: string}. Stored in human_edited_response, status=edited. Emits audit event.
GET/api/v1/ai/logs/pending-review
All pending AI outputs across all cases. Sorted oldest-first (FIFO). Used for the Review Queue page.
GET/api/v1/ai/stats
Aggregate stats: total queries, avg confidence, approval rate, rejection rate, token usage, cost estimate. Manager/Admin only.

Prompt Registry System

Prompts are stored in the ai_prompts database table — versioned, not hardcoded in Python. This enables prompt improvements without code deployments.

-- Example: Go API calls Python AI service
POST /internal/ai/generate
{
  "prompt_slug": "case_summarize",
  "version": 3,           // pin version or use "latest"
  "variables": {
    "case_title": "Loan Default Investigation",
    "doc_count": 5,
    "event_count": 23,
    "note_count": 4,
    "context_documents": "..."
  }
}

-- Python renders Jinja2 template from DB:
prompt = prompt_registry.render("case_summarize", version=3, variables=vars)

-- version 3: weight=0.7 (70% of traffic)
-- version 4: weight=0.3 (30% of traffic — testing new prompt)

Anti-Hallucination: Technical Implementation

RULE 1
Every response cites its source
Python RAG service includes top-k chunks in citations array: [{doc_id, doc_name, page, excerpt, similarity_score}]. Stored in citations JSONB. Frontend AICard component requires citations prop — TypeScript compile error if omitted.
RULE 2
Confidence score on every output
Computed from similarity scores (RAG) or context richness (summarization). Stored as NUMERIC(3,2). ConfidenceBar component shows colored indicator on every AI card — cannot be suppressed.
RULE 3
"Insufficient context" — never guess
System prompt includes sentinel instruction. Python response_parser.py detects INSUFFICIENT_CONTEXT → returns {error: "insufficient_context", message: "Not enough documents in this case to answer that question."}. Frontend shows this message verbatim — no fallback guess.
RULE 4
Human review gate
All responses default status='pending'. Case record APIs filter out pending AI outputs. No AI content appears in case summaries or reports until status IN ('approved','edited'). Enforced at DB query level — not just UI.
RULE 5
Visual distinction — always
AICard React component enforces required props via TypeScript: badge, confidence_score, citations, review_status. Build fails if any AI response is rendered without these markers.
RULE 6
Prompt injection prevention
Python pii_masker.py sanitizes input: strip HTML tags, escape special chars, detect adversarial patterns ("ignore previous instructions", "you are now a", "disregard your"). Returns 400 if detected. Sanitized input stored in audit log.
RULE 7
PII masking before every LLM call
Presidio Analyzer detects: PAN, Aadhaar, phone, email, bank account, IFSC codes. Tokens replace originals: [PAN_1], [PHONE_1]. LLM never sees raw PII. ai_logs.prompt_text stores only the masked version. Token map held in memory for request duration — never persisted.
RULE 8
Full logging of every interaction
Python AI service calls POST /internal/ai/log synchronously after every LLM response. If logging fails → the LLM response is discarded, error returned to user. "If it isn't logged, it didn't happen."

Pending Review Queue

A dedicated page listing all AI outputs awaiting human review across all cases. Purpose: prevent AI outputs from sitting in "pending" state indefinitely.

Sort Order
Oldest first (FIFO). Items pending >4 hours show an amber "Overdue Review" indicator. SLA configurable by admin.
Filters
Filter by: action_type, confidence_score range, case_id, triggered_by. Quick filters: "Low confidence only", "My cases only".
Bulk Approve
Select multiple items → "Bulk Approve". Intended for high-confidence, low-stakes outputs. Each approval still logged individually in audit_logs.
Review SLA Alert
River job checks every 30 min for items pending >4 hours → sends notification to analyst and manager. Prevents stale AI outputs.

Compliance Narrative

How OpsOwl AI satisfies regulatory AI governance requirements

RBI AI Governance Framework: Requires human oversight for AI decisions in financial services. OpsOwl AI's human review gate ensures no AI output becomes part of a case record without explicit human approval — with a full trail of who approved what, when, and why they may have edited it.

Explainability Requirement: Confidence scores and source citations allow investigators to explain any AI-assisted decision to an auditor: "The AI flagged this case at 87% confidence, citing these three specific document excerpts, and Analyst Priya S. approved it on May 15, 2026 at 14:32 IST."

PII Protection: Presidio masking before every LLM call ensures customer PII (Aadhaar, PAN, account numbers) is never transmitted to external AI providers. This satisfies data localisation concerns for on-prem deployments.

Sales Advantage: When a compliance officer asks "Can you show me every AI decision made on this case?" — OpsOwl AI's answer is yes, with a complete timeline, confidence levels, source citations, and human approvals. This is a direct competitive differentiator versus generic AI tools.

Frontend Components

AICard (core component)
Required props: action_type, response_text, confidence_score, citations[], review_status, model_used, latency_ms, tokens. Always renders with violet border, badge, confidence bar, citation panel, and action buttons.
ConfidenceBar
Reusable. Props: score (0–1). Green ≥0.8, amber 0.5–0.79, red <0.5. Shows percentage text + colored bar. Used across all AI output displays.
CitationPanel
Collapsible accordion. Shows source document name, page number, excerpt, similarity score. Click citation → opens document at that page.
ReviewModal
Full-screen modal: Approve / Edit (Tiptap editor) / Reject (reason required). Keyboard: Enter=Approve, Escape=Close.
PendingReviewQueue page
Virtualized list of pending items. Filter bar. Bulk approve button. Overdue indicators. Accessible at /ai/review-queue.
AIStats Dashboard
Admin page: total queries, approval rate (%), avg confidence, cost by model. CSS-only charts. Date range filter.
