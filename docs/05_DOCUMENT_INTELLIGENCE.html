Document Upload & Intelligence

Investigators work with large volumes of unstructured documents — bank statements, KYC records, legal letters, contracts, and photo IDs. OpsOwl AI processes, indexes, and makes every document queryable via AI, turning static attachments into live investigation context.

Module: internal/documents
Service: Go + Python AI
Storage: MinIO / S3
Queue: River (Postgres)
Phase: MVP
§ 01

Feature Overview

Every investigation in OpsOwl AI revolves around evidence — and evidence lives in documents. Bank statements reveal transaction patterns. KYC documents establish identity. Legal letters define obligations. Contracts expose counterparty risk. Photo IDs confirm who is who.

The Document Intelligence system handles the full lifecycle: upload → validate → store → extract → embed → index → query. Once a document is attached to a case, its full text content becomes part of the AI's context window when investigators ask questions or generate summaries.

📤 Upload

Drag-and-drop or file picker. Multipart POST. Immediate validation before any storage.

🔬 Extract

PyMuPDF for PDFs, Tesseract OCR for images and scanned docs, python-docx/openpyxl for Office formats.

🧠 Embed

Text chunked into ~500-token segments. Each chunk embedded via OpenAI or Anthropic. Stored in pgvector.

🔍 Query

AI Copilot performs semantic search across case documents. Results ranked by cosine similarity.

💡

Every document attached to a case becomes part of the AI context. The AI Copilot never operates on raw files — it operates on extracted, chunked, and indexed text, ensuring consistent performance regardless of source format.

§ 02

Supported File Types

📄
.PDF
Text extraction via PyMuPDF (fitz). If text layer is absent or sparse (<50 chars/page), automatically falls back to Tesseract OCR per page. Handles scanned bank statements natively.
📝
.DOCX / .DOC
Extracted via python-docx. Paragraphs, headings, table cells, and inline text are all captured. Legacy .doc files converted via LibreOffice headless before extraction.
📊
.XLSX / .XLS
Tabular data extracted via openpyxl. Each sheet becomes a structured text block with headers and rows preserved. Ideal for bank ledger exports and transaction dumps.
🖼️
.JPG / .PNG / .TIFF
Full OCR via Tesseract (eng+hin language packs). TIFF supported for multi-page fax documents. Image preprocessing (deskew, contrast) applied before OCR.
50 MB
Maximum size per file
500 MB
Maximum total per case
⚠️

Executable files (.exe, .sh, .bat, .js, .py, .zip, .jar) are rejected at the Go middleware layer before any processing. File type is determined by magic bytes (libmagic), not file extension.

§ 03

Document Processing Pipeline

Processing is fully asynchronous via the River job queue (backed by PostgreSQL). The upload request returns immediately after validation and storage; the heavy lifting happens in background workers.

📤
1 — Upload & Validate

Client POSTs multipart form data. Go middleware validates file size, MIME type (magic bytes), and extension allowlist. Request is rejected immediately if validation fails — nothing is written.

Go chi router magic bytes check reject if invalid
🔬
2 — Virus Scan

File content is streamed to ClamAV daemon via TCP socket. If ClamAV returns a threat signature, the upload is rejected and the threat is logged. No file reaches permanent storage without passing the scan.

ClamAV integration TCP socket scan stream — no temp disk write
🗃️
3 — Store in MinIO / S3

Clean file is written to object storage at path {org_id}/{case_id}/{doc_id}/{filename}. Document metadata row is inserted into documents table with status = 'pending'.

MinIO / S3 documents.status = pending
📋
4 — Enqueue River Job

A DocumentProcessingJob is inserted into River's job table (in the same Postgres transaction as the document row). Atomicity guaranteed — if job enqueue fails, document insert rolls back.

River job queue atomic with DB insert
🤖
5 — Text Extraction (Python AI Service)

River worker calls POST /process-document on the Python AI service. The service downloads the file from MinIO/S3 and runs the appropriate extractor (PyMuPDF → OCR fallback, python-docx, openpyxl, Tesseract). Raw text is returned to the worker. Document status set to processing.

FastAPI PyMuPDF Tesseract OCR
✂️
6 — Chunk Text

Extracted text is split into ~500-token segments with 50-token overlap. Chunking respects sentence boundaries and paragraph breaks where possible. Each chunk records its source page number for provenance.

~500 tokens / chunk 50-token overlap page provenance tracked
🧮
7 — Generate Embeddings

Each chunk is embedded via POST /embed-chunks. Default model: OpenAI text-embedding-3-small (1536 dimensions). Fallback: Anthropic voyage-3-lite. Embeddings are batch-generated (up to 100 chunks per API call). Stored in document_chunks.embedding vector(1536).

text-embedding-3-small 1536 dimensions pgvector storage
✅
8 — Complete & Notify

Document status updated to completed (or failed with error message). A document_processed timeline event is emitted. Case viewers receive an SSE push notification — no page refresh needed.

documents.status = completed SSE notify timeline event
§ 04

Database Schema

Three tables cover the document lifecycle. All use UUID v4 primary keys, TIMESTAMPTZ, and enforce foreign keys with indexed FK columns.

SQL — PostgreSQL 18
-- ────────────────────────────────────────────────────────────
-- documents: core document metadata
-- ────────────────────────────────────────────────────────────
CREATE TYPE document_processing_status AS ENUM (
  'pending', 'processing', 'completed', 'failed'
);

CREATE TABLE documents (
  id                   UUID            PRIMARY KEY DEFAULT gen_random_uuid(),
  case_id              UUID            NOT NULL REFERENCES cases(id) ON DELETE CASCADE,
  uploaded_by          UUID            NOT NULL REFERENCES users(id),
  original_filename    TEXT            NOT NULL,
  stored_path          TEXT            NOT NULL,             -- {org_id}/{case_id}/{doc_id}/{filename}
  file_type            TEXT            NOT NULL,             -- pdf, docx, xlsx, jpg, png, tiff
  mime_type            TEXT            NOT NULL,
  file_size_bytes      BIGINT          NOT NULL,
  processing_status    document_processing_status NOT NULL DEFAULT 'pending',
  page_count           INTEGER,                               -- populated after extraction
  extracted_text_path  TEXT,                                  -- MinIO path to raw extracted text
  created_at           TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
  updated_at           TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
  deleted_at           TIMESTAMPTZ
);

CREATE INDEX idx_documents_case_id         ON documents (case_id);
CREATE INDEX idx_documents_uploaded_by      ON documents (uploaded_by);
CREATE INDEX idx_documents_processing_status ON documents (processing_status) WHERE deleted_at IS NULL;
CREATE INDEX idx_documents_deleted_at        ON documents (deleted_at) WHERE deleted_at IS NOT NULL;

-- ────────────────────────────────────────────────────────────
-- document_chunks: text chunks with vector embeddings
-- ────────────────────────────────────────────────────────────
CREATE TABLE document_chunks (
  id           UUID           PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id  UUID           NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  case_id      UUID           NOT NULL REFERENCES cases(id) ON DELETE CASCADE,
  chunk_index  INTEGER        NOT NULL,
  content      TEXT           NOT NULL,
  embedding    vector(1536)  NOT NULL,              -- OpenAI text-embedding-3-small
  page_number  INTEGER,                               -- source page (null for non-paged formats)
  created_at   TIMESTAMPTZ    NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_chunks_document_id  ON document_chunks (document_id);
CREATE INDEX idx_chunks_case_id      ON document_chunks (case_id);
-- HNSW index for fast cosine similarity search:
CREATE INDEX idx_chunks_embedding ON document_chunks
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);

-- ────────────────────────────────────────────────────────────
-- document_processing_jobs: tracks River job lifecycle
-- ────────────────────────────────────────────────────────────
CREATE TABLE document_processing_jobs (
  id            UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id   UUID        NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  status        TEXT        NOT NULL DEFAULT 'queued',
  error_message TEXT,
  started_at    TIMESTAMPTZ,
  completed_at  TIMESTAMPTZ,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_proc_jobs_document_id ON document_processing_jobs (document_id);
CREATE INDEX idx_proc_jobs_status      ON document_processing_jobs (status)
  WHERE status IN ('queued', 'processing');
§ 05

Storage Strategy

OpsOwl AI uses an S3-compatible object storage interface. In development and on-premise deployments, MinIO provides a self-hosted S3-compatible server. In cloud deployments, the same interface targets AWS S3. No code changes are required between environments — only configuration.

Path Convention

{org_id}/{case_id}/{doc_id}/{original_filename}

Example: org_9f3a.../case_d12b.../doc_47cc.../bank_statement_jan2025.pdf

Presigned URL Access

Files are never served directly. All download access is via presigned URLs generated at request time with a 1-hour expiry. The URL is generated server-side, includes the requester's identity in the audit log, and is single-use scoped.

1-hour URL expiry audit logged on every generate no direct bucket access

Environment Mapping

Development / On-Prem

MinIO runs as a Docker container. Bucket: opsowl-documents. Endpoint configured via STORAGE_ENDPOINT env var.

Cloud Production

AWS S3 bucket in ap-south-1 (Mumbai) for Indian data residency. IAM role with least-privilege GetObject/PutObject. No public bucket policy.

✅

The Go storage client is defined as an interface (StorageClient). Both MinIO and S3 implement it. Tests use a mock implementation. No AWS SDK leakage into business logic.

§ 06

Security

  • 🛡️ Virus scanning (ClamAV) — every uploaded file is streamed to ClamAV before storage. ClamAV runs as a sidecar container. The Go service connects via TCP to clamd. Files containing known malware signatures are rejected and the event is logged with severity CRITICAL.
  • 🛡️ Magic bytes validation — MIME type is determined by reading the file's magic bytes (using net/http.DetectContentType + custom signatures), never trusting the Content-Type header or file extension. A .pdf extension with a ZIP magic byte is rejected.
  • 🛡️ Extension allowlist — only PDF, DOCX, DOC, XLSX, XLS, JPG, JPEG, PNG, TIFF are accepted. Executables (.exe, .sh, .bat), archives (.zip, .tar, .gz), scripts (.js, .py, .rb) are blocked at the middleware layer.
  • 🛡️ Presigned URL expiry — download URLs expire after 1 hour. Each generation is logged with the requesting user ID, timestamp, and document ID. Links cannot be shared externally without also sharing authentication context.
  • 🛡️ RBAC enforcement — document endpoints verify that the requesting user is a member of the case's organization and has at least Investigator role. Upload requires write permission. Delete requires case owner or admin role.
  • 🛡️ No executables stored — the allowlist combined with magic byte checking ensures no executable content can be stored, even in renamed form.
  • 🛡️ PII masking before AI calls — Aadhaar numbers, PAN, account numbers, and phone numbers are masked in extracted text before embedding and before sending to AI providers. Raw PII never leaves the Postgres/MinIO perimeter.
§ 07

API Endpoints

All responses follow the envelope {"data": ..., "meta": ..., "error": null}. Cursor pagination used for list endpoints. Authentication required on all routes (JWT RS256).

POST
/api/v1/cases/:id/documents
Multipart file upload. Validates type + virus scan → stores → enqueues processing job. Returns document metadata with status: "pending".
GET
/api/v1/cases/:id/documents
List all documents for a case. Cursor paginated. Includes processing_status, file_type, file_size_bytes, page_count. Excludes soft-deleted rows.
GET
/api/v1/cases/:id/documents/:doc_id
Single document metadata. Includes uploader info, timestamps, processing status, page count.
GET
/api/v1/cases/:id/documents/:doc_id/download
Generates a presigned URL (1-hour expiry) and returns it. Client uses the URL to download directly from MinIO/S3. Download is logged for audit.
GET
/api/v1/cases/:id/documents/:doc_id/status
Processing status polling endpoint. Returns { status, page_count, chunk_count, error_message }. Used by frontend before SSE is established.
DELETE
/api/v1/cases/:id/documents/:doc_id
Soft delete (sets deleted_at). Schedules async job to delete MinIO/S3 object and all associated chunks + embeddings. Requires admin or case owner role.

River Job (Internal)

The document processing pipeline runs as a River worker inside the Go service. It is not an HTTP endpoint — River pulls jobs from the Postgres-backed queue. The worker calls the Python AI service via HTTP. Retries: 3 attempts with exponential backoff. Dead-letter: failed jobs remain in document_processing_jobs with status = 'failed'.

SSE Events (document processing)

event: document_processed
data: {"document_id":"uuid","status":"completed","chunk_count":42,"page_count":18}
event: document_processing_failed
data: {"document_id":"uuid","status":"failed","error":"OCR timeout after 120s"}

§ 09

Python AI Service Endpoints

The Python AI service exposes two internal HTTP endpoints called exclusively by the Go River worker. These are not exposed to the public internet. mTLS or shared secret header for service-to-service auth.

Python — FastAPI
# POST /process-document
# Called by Go River worker after file is stored in MinIO/S3.
# Downloads the file, runs appropriate extractor, returns raw text + metadata.

class ProcessDocumentRequest(BaseModel):
    document_id: str
    stored_path: str              # MinIO/S3 path
    file_type:   str              # pdf | docx | xlsx | jpg | png | tiff
    org_id:      str

class ProcessDocumentResponse(BaseModel):
    document_id:    str
    raw_text:       str
    page_count:     int
    extraction_method: str        # pymupdf | tesseract | python-docx | openpyxl
    char_count:     int

@router.post("/process-document")
async def process_document(req: ProcessDocumentRequest) -> ProcessDocumentResponse:
    file_bytes = await storage.download(req.stored_path)
    extractor  = get_extractor(req.file_type)    # factory: PDF|DOCX|XLSX|image
    result     = await extractor.extract(file_bytes)
    return ProcessDocumentResponse(**result)

# ────────────────────────────────────────────────────────────
# POST /embed-chunks
# Accepts up to 100 text chunks, returns embeddings.
# ────────────────────────────────────────────────────────────

class EmbedChunksRequest(BaseModel):
    document_id: str
    case_id:     str
    chunks:      list[ChunkInput]  # {chunk_index, content, page_number}
    model:       str = "text-embedding-3-small"

class EmbedChunksResponse(BaseModel):
    embeddings:  list[ChunkEmbedding]  # {chunk_index, embedding: list[float]}
    model_used:  str
    token_count: int

@router.post("/embed-chunks")
async def embed_chunks(req: EmbedChunksRequest) -> EmbedChunksResponse:
    embeddings = await embedding_provider.embed_batch(
        texts=[c.content for c in req.chunks],
        model=req.model
    )
    return EmbedChunksResponse(embeddings=embeddings, ...)
💡

The embedding provider is an abstraction over OpenAI and Anthropic SDKs. Switching providers requires only changing the EMBEDDING_PROVIDER env var. Vector dimension must match the pgvector column — if provider changes, a migration is required to re-embed all chunks.

§ 11

On-Prem Deployment Strategy

Many fintech and NBFC customers operate under strict data residency requirements — RBI guidelines often mandate that sensitive financial data must not leave the customer's data centre. OpsOwl AI's architecture is designed for true on-premise deployment with zero cloud dependencies.

MinIO = Self-hosted S3

MinIO is S3-protocol-compatible. The Go StorageClient interface works identically against MinIO or S3. Customers run MinIO on their own hardware.

No Data Egress

Documents, extracted text, and embeddings never leave the customer's network. Even AI calls can be routed to an on-prem LLM (Ollama) by swapping the embedding provider config.

Docker Compose Stack

Full stack ships as a Docker Compose file: Go API, Python AI service, Postgres + pgvector, MinIO, ClamAV. One command deployment for on-prem teams.

Kubernetes Support

Helm chart provided for K8s deployments. MinIO Operator supported. PVC-backed storage for MinIO persistence. StatefulSet for Postgres with WAL archiving.

✅

The same Docker image is deployed to cloud (S3 endpoint) and on-prem (MinIO endpoint). The only difference is environment variables: STORAGE_ENDPOINT, STORAGE_ACCESS_KEY, STORAGE_SECRET_KEY.

§ 12

Test Strategy

File Type Validation

  • PDF with valid magic bytes → accepted
  • ZIP renamed to .pdf → rejected
  • EXE with any extension → rejected
  • Empty file → rejected
  • Over 50MB → rejected pre-scan
  • Content-Type spoofing → ignored

Processing Pipeline

  • PDF extraction returns text
  • Scanned PDF falls back to OCR
  • XLSX extraction preserves table structure
  • Chunking respects 500-token limit
  • Embeddings have correct dimension (1536)
  • Failed job sets status = failed

Storage (Mock)

  • Path follows org/case/doc/filename convention
  • Presigned URL generated with 1hr expiry
  • Delete removes MinIO object
  • StorageClient interface mock used in unit tests
  • MinIO integration tests use testcontainers

API Integration

  • Unauthorized request → 401
  • Wrong org → 404
  • Upload with virus → 422 with error
  • Processing status polling
  • SSE event received after completion
  • Soft delete does not expose in list
